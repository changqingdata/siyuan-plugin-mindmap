# 大纲导图 · 专业级交互与视觉优化方案

> 基于 2026-09-19 的首次真机运行截图与源码走查。
> 本文档只做分析与方案设计，**未修改任何源码**。

---

## 零、先说结论：有一个根因级 bug 在拖累一切

截图里「无敌绿考」竖成 4 行、每个节点竖成 3 行，**不是审美取舍，是节点宽度算错了**。

### 根因链

```
.mm-world  { position: absolute; width: auto }   ← 宽度此时未设置
.mm-nodes  { position: absolute; width: auto }   ← 无在流子元素 → 收缩宽度 = 0
.mm-node   { position: absolute; width: auto }   ← 包含块宽度 = 0
.mm-txt    { min-width: 0; word-break: break-word }
```

关键在 `renderer.ts:343-346`：

```ts
// 批量读尺寸
for (const n of all) {
    n.w = n.el!.offsetWidth;   // ← 此刻 worldEl.style.width 还没设
    n.h = n.el!.offsetHeight;
}
```

而 `worldEl.style.width` 是在 `renderer.ts:361` 才赋值的 —— **在测量之后**。

于是测量时：

1. `.mm-nodes` 是绝对定位、`width: auto`，且它的子元素（`.mm-node`）全部脱离文档流 → 它的 shrink-to-fit 宽度 = **0**。
2. `.mm-node` 的包含块宽度 = 0，`width: auto` 的绝对定位元素退化为 **min-content 宽度**。
3. `.mm-txt` 上的 `word-break: break-word` 等价于 `overflow-wrap: anywhere`，**会参与 min-content 计算**；即使不算它，CJK 本来就能在任意两字之间断行。所以 min-content = **一个汉字**。

结果：所有节点宽度 = 1 个字符宽。

### 连带后果（截图里的其他异常都是它引起的）

- **整张导图缩在画布中央一小块**：世界坐标尺寸被压到极小，`fit()` 里 `scale = Math.min(vw/w, vh/h, 1.15)` 恒等于上限 `1.15`，永远填不满画布 → 周围大片空白。
- **折叠按钮位置飘忽**：`renderer.ts:464` 用 `left: calc(100% + 5px)` 相对节点定位，节点宽度错了，圆点自然压到卡片边缘上（截图右侧那些小圆圈）。

### 修复方向

```css
.mm-root .mm-node { width: max-content; }
.mm-root .mm-txt  { max-width: 240px; }   /* 超长文本的换行上限 */
```

`width: max-content` 让节点**完全绕过 shrink-to-fit**，不再受包含块宽度影响，测量顺序问题一并消失。

同时建议 `renderer.ts:373` 不要再回写 `el.style.width = n.w` —— 让 CSS 决定宽度，JS 只读取，避免"测量值被固化后无法响应字体变化"。

> **这一条改完，导图的观感提升幅度会超过后面所有视觉优化加起来。**

## 一、交互方案

### 1.1 好消息：地基已经在了

`renderer.ts:546-568` 已经有 `select(n)` / `this.selected` / `mm-sel` / `mm-dim`，
而且 `refreshSelection()` 已经实现了**祖先路径高亮 + 其余分支淡出**。

也就是说「当前节点」这个概念是存在的，只是**没有任何键盘入口**。

全仓库唯一的 `keydown` 监听在 `renderer.ts:668`，位于改名输入框内部，只处理 Enter / Esc。
导图容器没有 `tabindex`，没有焦点管理，没有键盘导航。

**所以快捷键不是从零造轮子，而是给已有的选中模型接上键盘。**

### 1.2 三态焦点模型（一切快捷键的前提）

```
        点击节点 / 方向键
浏览态 ───────────────────→ 选中态
   ↑                          │  ↑
   │   Esc / 点击空白          │  │  Enter 提交 / Esc 取消
   └──────────────────────────┘  │
                                 ↓
                              编辑态（contenteditable 接管键盘）
```

三个状态的职责必须严格分开：

| 状态 | 键盘归属 | 视觉反馈 | 退出方式 |
|---|---|---|---|
| 浏览态 | 思源编辑器 | 无 | — |
| 选中态 | **导图拦截** | 焦点环 + 路径高亮 | Esc / 点击空白 |
| 编辑态 | contenteditable | 输入光标 + 强调描边 | Enter 提交 / Esc 取消 |

**进入选中态的显式动作**：单击任意节点。这是唯一入口，避免导图在后台偷键盘。

### 1.3 快捷键映射

对齐 XMind / MindNode 的肌肉记忆，不另造一套。

#### A. 导航（纯视图，不写回块）

| 按键 | 行为 |
|---|---|
| `↑` / `↓` | 同级上一个 / 下一个 |
| `←` | 回到父节点 |
| `→` | 进入第一个子节点（若已折叠则先展开） |
| `Home` / `End` | 同级第一个 / 最后一个 |
| `空格` | 折叠 / 展开当前节点 |
| `Ctrl+A` | 全选同级；再按一次全选全部 |
| `Ctrl+F` | 搜索框，输入即高亮匹配，Enter 跳下一个 |
| `Esc` | 逐级退出：编辑态 → 选中态 → 无选中 |

#### B. 结构编辑（写回思源块）

| 按键 | 行为 | 块 ID 是否保真 |
|---|---|---|
| `Tab` | 新建子节点，并立即进入编辑态 | ✅ |
| `Enter` | 新建同级节点（当前之后） | ✅ |
| `F2` / 双击 | 重命名当前节点 | ✅ |
| `Delete` / `Backspace` | 删除当前节点及子树（需确认） | — |
| `Ctrl+↑` / `Ctrl+↓` | 同级上移 / 下移 | ✅ |
| `Alt+←` | 升级（outdent） | ✅ |
| `Alt+→` | 降级（indent，成为上一个兄弟的子节点） | ✅ |
| `Ctrl+C` / `X` / `V` | 复制 / 剪切 / 粘贴子树 | 副本 |
| `Ctrl+D` | 快速复制为同级 | 副本 |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 撤销 / 重做 | ⚠️ 见第五节 |

#### C. 视图

| 按键 | 行为 |
|---|---|
| `Ctrl` + `=` / `-` | 放大 / 缩小 |
| `Ctrl+0` | 适应画布 |
| `Ctrl+1` | 回到 100% |
| `F` | 全屏（inline 模式） |
| `Ctrl+滚轮` | 缩放（已实现） |

### 1.4 与思源编辑器的冲突处理（实现难点）

这是整块交互方案里**最容易翻车的地方**，必须专门设计：

1. **容器 `tabindex="0"`**，`keydown` 挂在 `.mm-root` 上。焦点不在导图内时完全不响应。
2. **必须 `stopPropagation()` + `preventDefault()`**。否则：
   - `Tab` 会插入制表符或跳转到下一个块
   - `Ctrl+A` 会全选整个文档
   - `Delete` 会删掉编辑器里选中的内容
   - 方向键会让光标在正文里移动
3. **留白名单放行**：`Ctrl+S`（保存）、`Ctrl+P`、`F5` 等浏览器/系统级快捷键不要拦。
4. **编辑态交还键盘**：进入改名输入框后，除了 `Enter` / `Esc` / `Tab`，其余按键一律放行给 `contenteditable`，尤其不要拦 `Ctrl+A` / `Ctrl+C` / `Ctrl+V`。
5. **冲突优先级原则**：焦点在导图内 = 导图优先。这是 XMind、Figma 这类工具的标准做法，符合直觉。
6. **必须有明确的"离开导图"路径**：`Esc` 逐级退出 + 点击导图外部自动失焦。否则用户会被"困"在导图里。

### 1.5 其它交互增强

| 增强 | 说明 | 优先级 |
|---|---|---|
| **hover 快捷按钮** | 鼠标悬停时节点旁出现 `+`（加子节点）和 `⌄`（折叠），把最高频的两个操作从右键菜单里解放出来 | P1 |
| **拖拽自动展开** | 拖拽经过折叠节点悬停 400ms 自动展开 | P2 |
| **拖拽边缘自动滚动** | 拖到画布边缘时视口自动平移 | P2 |
| **框选多选** | 空白区拖拽框选，支持批量删除/移动/折叠 | P3 |
| **菜单显示快捷键** | 右键菜单项右侧标注对应按键，形成学习闭环 | P1 |
| **自建 tooltip** | 现在用原生 `title`，有延迟、样式不可控、暗色主题下难看。换成自绘 tooltip，可附带快捷键提示 | P1 |
| **双击空白 = 适应画布** | 一个很顺手的习惯动作 | P2 |

## 二、视觉方案

### 2.1 节点层级体系

现在 `d0 / d1 / d2` 只差字号（15.5 / 13.5 / 12.5）和内边距，在暗色背景上几乎看不出主次。建议 token 化：

| 层级 | 字号 | 字重 | 内边距 | 圆角 | 视觉处理 |
|---|---|---|---|---|---|
| 中心主题 `d0` | 16px | 600 | 12 / 22 | 12px | 实心填充 + 柔和投影 + 1px 内高光描边 |
| 一级分支 `d1` | 14px | 600 | 9 / 16 | 10px | 分支色 8% 填充 + 30% 描边，文字取分支色 |
| 二级 `d2` | 13px | 500 | 8 / 14 | 8px | 中性卡片 + 左侧 3px 分支色条 |
| 三级及以下 `d3+` | 12.5px | 400 | 7 / 12 | 8px | 同 d2，色条降到 2px，整体更轻 |

宽度规则：

```css
width: max-content;
min-width: 56px;      /* 防止单字节点过窄 */
max-width: 240px;     /* 长文本换行上限 */
```

### 2.2 连线打磨

现状 `renderer.ts:502-542` 是**等宽单段贝塞尔**，`width = max(1.3, 2.6 - (depth-1) * 0.35)`，三级之后就掉到 1.3px 了。

| 问题 | 改进 |
|---|---|
| 等宽，无粗细变化 | **渐细**：父端 2.4px → 子端 1.2px |
| 同级分支各画各的 | **主干汇聚**：父节点先引出一条主干，再从主干分叉成梳状。这是专业导图最明显的观感差异 |
| 端点落在节点外接框边缘 | 加连接点偏移量，让线端点**贴在卡片边框上**，而不是外接框上 |
| 控制点算法在短距离时画得很鼓 | `dx = min(|x2-x1| * 0.5, 60)`，并保证最小 12px |
| 按 depth 线性衰减透明度（`1 - (depth-1)*0.17`），深层几乎看不见 | 改为按分支色 × 0.6 透明度，**同一分支内保持一致**，用粗细而非透明度表达层级 |

### 2.3 色彩

现有的 `--mm-*` token 体系（`theme.ts:4-20`）设计得很好 —— 所有颜色通过自定义属性注入、CSS 不直接引用 `--b3-*`，这保证了 SVG 导出能完整还原外观。**继续沿用这个约束。**

- 暗色主题下降低分支色饱和度、提高明度，保证文字与背景对比度 **≥ 4.5:1**（WCAG AA）
- 建议主题从 5 套扩到 6 套：思源自适应 / 极简 / 深空 / 纸感 / 莫兰迪 / **高对比度**（无障碍）
- 高对比度主题需要关闭所有投影、描边加粗到 1.5px、文字用纯色

### 2.4 工具栏重构

现在（`renderer.ts:193-256`）是一排纯文字按钮，无图标、无分组、无激活态提示。

```
[逻辑结构图|思维导图|树状图]  │  [− 100% + 适应]  │  [折叠 展开]  │  [导出 全屏 退出]
       布局切换                 缩放                    折叠              动作
```

- 组间加 1px 分隔线
- 激活态用主题色填充（`mm-on` 已实现，保留）
- tooltip 自绘并附带快捷键提示
- **更激进的做法**：默认隐藏工具栏，鼠标移入导图才淡入（参考 Notion 块工具栏）。视觉噪音能降一大截。

### 2.5 画布

- 网格已有（`.mm-root` 的 `background-image` 24px 网格），但太淡，截图里几乎看不见 → 透明度提到 0.04~0.06，做到"可见但克制"
- **空状态**：列表为空时给引导提示，而不是一片空白
- **右下角缩放胶囊**：常驻 `− 100% +`，比顶部工具栏更符合导图习惯
- **小地图**：节点 > 50 时显示，大图导航必需
- 外边框：现在是 `1px solid` + `border-radius: 10px`，在思源暗色主题里略显生硬 → 去掉边框，改用背景色微差区分

### 2.6 动效（专业感的关键）

| 场景 | 动效 |
|---|---|
| 节点出现 / 消失 | 160ms `opacity` + `translateY(4px)` |
| **布局变化** | **FLIP**：先记录旧位置 → 改布局 → 反向位移 → transition 归位 |
| 折叠 / 展开 | 高度 + 透明度过渡 |
| 拖拽落点 | 指示线带轻微弹性 |

> **FLIP 是"手感"和"能用"的分水岭。** XMind 那种顺滑感主要来自它：任何结构变化时，节点都是"滑过去"而不是"瞬移"。
>
> 全部动效包在 `@media (prefers-reduced-motion: no-preference)` 内，节点数 > 300 时自动关闭。

改完后重点回归这几项：

- [ ] 节点文字不再逐字换行，长文本在 240px 处正常折行
- [ ] 导图能撑满画布（`fit()` 的 scale 不再恒为 1.15）
- [ ] 折叠按钮稳定贴在节点右侧，不压边
- [ ] 在导图内按 `Tab` 不会往正文插制表符
- [ ] 在导图内按 `Ctrl+A` 不会全选整个文档
- [ ] 进入改名输入框后，`Ctrl+C` / `Ctrl+V` / 方向键行为正常
- [ ] `Esc` 能逐级退出，不会把用户困在导图里
- [ ] 结构编辑后块 ID 是否保留（对照 `actions.ts` 的等价表）

## 五、边界与风险（必须在动手前确认）

### 5.1 撤销归属 ⚠️ 最高优先级验证项

导图的写回走的是思源内核 API，而思源的 undo 栈记录的是**编辑器内的操作**。
**导图触发的块操作能否被 `Ctrl+Z` 撤销，目前完全未知，必须先实测。**

两种结果：

- 能撤销 → 直接把 `Ctrl+Z` 透传给思源即可，皆大欢喜
- 不能撤销 → 要么接受并明确告知用户（推荐，成本低），要么在插件内自建操作栈。
  自建栈的代价很大，而且会和思源的 undo 打架（用户按一次 `Ctrl+Z`，到底撤哪个？）。**不建议自建。**

### 5.2 块 ID 保真

`moveBlock` 内核 API 只接受 `id` / `previousID`（移到某块**之后**）/ `parentID`（追加到容器**末尾**），**没有 `nextID`**。
所以"在某个节点**之前**插入"这种位置表达不出来，只能走"复制 + 删除"的副本路径 —— **带块引用的节点会失效**。

影响 `Shift+Enter`（在当前节点之前插入同级）。建议：**这个快捷键先不做**，或做了但给出明确警告。

### 5.3 快捷键冲突

思源本身有大量快捷键，导图获得焦点时拦截是必要的，但必须：
- 维护白名单（`Ctrl+S` 等系统级快捷键放行）
- 在设置里允许用户**关闭整套导图快捷键**（逃生舱）

### 5.4 导出友好性约束

`exporter.ts` 走的是 SVG 重写路径。**任何新视觉特性都必须在导出路径里能复现。**

- CSS 渐变 / 滤镜 / 动效 → 导出时无法序列化，要提前设计成可复现的形式
- 现有的 `--mm-*` token 体系正是为此而设，**必须延续**
- 主干汇聚的连线如果用了 `<linearGradient>`，导出时要一并写出 `<defs>`

### 5.5 性能

- FLIP 动效 + `will-change` 要节制使用，否则大量节点时内存和合成层开销会爆炸
- 建议：节点 > 300 关闭动效；`will-change` 只在拖拽/缩放期间挂载，结束后移除

# 画布与工具交互增强建议

> 第十五轮 · 仅方案，未改动任何代码
> 审视对象：当前工具条（布局切换 / 折叠全部 / 展开全部 / 搜索 / 导出 / 全屏 / 回大纲 / 缩放条 / 小地图 / 面包屑）与画布本体交互

---

## 0. 先说结论

当前这版的功能**密度**已经够了 —— 布局、折叠、搜索、导出、下钻、框选、拖拽、多选、键盘全都有。
真正缺的不是「再加几个按钮」，而是三件事：

| 缺口 | 一句话描述 | 为什么现在最痛 |
| --- | --- | --- |
| **A. 缺「编辑」这一档** | 现在只有「看」和「改单个节点」，没有「批量改结构」 | 结构操作一次只能作用于一个节点；多选了也只能看着 |
| **B. 缺「视图记忆」** | 布局/主题/缩放不跟文档走，换一篇就得重调 | 每次打开都在重复劳动，久了就不想用了 |
| **C. 缺「反馈」** | 操作成功/失败/进行中，全靠 `showMessage` 一闪而过 | 结构操作是异步写内核的，用户不知道到底成没成 |

下面按 **P0（先做）→ P1（值得做）→ P2（有余力再说）** 分档，每条都给「现状 → 方案 → 收益 → 代价」。
最后附一份「**不建议做**」的清单，免得越加越乱。

---

## P0 · 三条骨架级的

### P0-1 多选之后的批量操作条

**现状**
框选（拖拽空白）和 Ctrl 点选已经能选中多个节点了，但选完没有任何后续动作 ——
多选在功能上是个死胡同，用户框完只能按 Delete 删掉，或者一个个拖。

**方案**
选中 ≥2 个节点时，在**工具条下方浮出一条「批量操作条」**（不是弹窗，避免遮挡画布）：

```
┌──────────────────────────────────────────────────────────┐
│  已选 5 个  ·  [ 升级 ]  [ 降级 ]  [ 折叠 ]  [ 展开 ]  ·  [ 导出这些 ]  [ 删除 ]  [ ✕ ] │
└──────────────────────────────────────────────────────────┘
```

- **升级 / 降级**：批量改层级。这是最高频的诉求（「这几条都该是上一级的子节点」），
  现在只能一条条按 `Alt+→`。
- **折叠 / 展开**：只作用于「选中的这些节点」，与工具条上的「折叠全部」区分开。
- **导出这些**：只导出选中子树，直接复用已有的导出管线。
- **删除**：带撤销（撤销栈已经有了）。

**收益**：把「多选」从一个半成品变成真正能提效的功能。
**代价**：中等。`actions.ts` 里的每个结构操作要支持「批量」入口；
内核没有批量 API，批量 = 循环调用，所以必须**先算好全部计划再逐条执行**，
中途失败要能回滚（`history.ts` 的撤销记录已经能承载）。

---

### P0-2 结构操作的结果反馈

**现状**
`applyAction()` 里失败只有一句 `showMessage("操作未生效，请重试")`，
成功则**完全没有反馈**。而这条链路是异步的：写内核 → 内核回推 DOM → 扫描重挂视图，
中间隔了 140ms 扫描防抖 + 内核往返，用户点完「+」之后有 300~500ms 是**没有任何变化**的。

于是用户会：① 以为没点上，再点一次（结果插了两个）；② 以为插件坏了。

**方案**
两层反馈，都不打断操作：

1. **乐观占位**：点「+」的瞬间，先在导图上插一个半透明的「新节点」占位框（虚线边框 + 呼吸动画），
   位置按预期布局算好。等内核回推、视图重挂之后，占位框被真节点替换。
   这一条和本轮折叠同步用的「覆盖表」是同一个思路：**先给反馈，再等真相**。
2. **失败要显眼**：失败时不是弹一句提示，而是在**原节点上**打一个红色描边 + 抖动 200ms，
   并把失败原因放进 tooltip（「该块已被删除」「父列表已变更」）。

**收益**：消除「点了没反应」这个最容易劝退的体验断层。
**代价**：中等偏低。占位框可以复用 `createNodeEl`，只是加个 `mm-placeholder` 类。

---

### P0-3 视图状态跟文档走

**现状**
`layout / theme / edge / 缩放 / 平移` 全部是**全局设置**，不跟文档走。
在 A 文档里调成「思维导图 + 深色主题」，切到 B 文档也是这套；
反过来，B 文档本来调好的「树状图」，回到 A 又被改了。

**方案**
把「视图偏好」拆成两级：

- **全局默认**（设置面板里那套）—— 新文档第一次打开时用它。
- **文档级覆盖** —— 用户在这个文档里改过布局/主题之后，写进**块属性**
  （`custom-mindmap-view`，值形如 `logic|deep|1.25`），下次打开这个列表就恢复它。

关键设计：**只记「用户显式改过的项」**，没改过的继续跟随全局默认 ——
否则用户改了全局主题，所有文档都不跟着变，反而更别扭。

另外把**缩放与平移**也纳入：现在重新打开文档一定回到「适应画布」，
用户精心放大到某个分支看细节，切走再回来就没了。建议记 `scale`，
但**不记平移**（平移跟画布尺寸强相关，记了很容易错位）。

**收益**：从「每次都要重调」变成「打开就是上次的样子」。
**代价**：低。已经有 `custom-mindmap` 属性的读写管线，加一个属性即可。
注意要跟本轮「折叠状态完全跟随大纲」的原则一致 ——
**布局/主题是用户偏好，可以记；折叠是内容状态，必须交给大纲**，两者不要混。

## P1 · 让画布「会说话」

### P1-1 悬停预览：把隐藏的子树「透出来」

折叠一个节点之后，用户其实想知道「里面是什么」，但现在只有珠子上的数字。
**方案**：悬停折叠节点 600ms，在它旁边浮出一张小卡片，列出前 5 个子节点文字 + 「还有 N 个」。

顺带解决另一个问题：**拖拽时悬停自动展开**（已有 `HOVER_EXPAND_DELAY`）现在没有任何提示，
用户不知道「停一下会展开」。加一个环形进度指示就够了。

**代价**：低。纯 UI。

---

### P1-2 连线语义化

现在所有连线长得一样。但大纲里其实藏着信息：

- **任务列表**：`☑ 已完成` / `☐ 未完成` —— 已完成的子树连线可以用虚线。
- **有序列表**：层级编号已经在节点上显示了，连线粗细可以随层级递减（现在已经做了渐细）。
- **新插入的节点**：给一条 1.5s 的高亮描边，让用户知道「加在哪了」。

**代价**：低。`buildConnectors` 加一个 `style` 参数即可。

---

### P1-3 小地图增强：从「看的」变成「用的」

现在小地图只显示视口框，不能交互。
**方案**：

- 点击小地图 → 视图直接跳过去（现在只能拖视口框）。
- 小地图上**标出搜索命中点**（小黄点）和**选中节点**（小蓝点）。
- 节点数少（比如 < 30）时**自动隐藏小地图** —— 现在小图上也挂个小地图，纯占地方。

**代价**：低。

---

### P1-4 缩放条升级成「缩放菜单」

现在缩放条是 `[−] [100%] [+] [适应]`，点了 `100%` 是「回到 1.0」——
但用户真正想要的是「**缩放到能看清这个分支**」。

**方案**：把 `100%` 那个标签做成下拉：

```
[−] [ 100% ▾ ] [+] [适应]
        ├─ 100%
        ├─ 适应画布
        ├─ 适应选中节点        ← 新增
        ├─ 只看当前分支        ← 等价于下钻，但更直观
        └─ 记住这个缩放        ← 写进 P0-3 的文档级偏好
```

**代价**：低。

## 不建议做（明确劝退）

这些看起来诱人，但会破坏「大纲是唯一真相源」这个根基：

1. **不要在导图里直接新建「游离节点」** —— 所有节点必须是真实块，否则一保存就丢。
2. **不要让导图自己维护一份折叠状态** —— 本轮刚把这条拆掉，回到原生 `fold` 之后
   「大纲什么状态、导图就是什么状态」才是结构上成立的。
3. **不要加「自动整理布局」按钮** —— 导图的位置完全由布局算法推导，没有手工位置，
   所以这个按钮无处施力；真要「整理」，用户需要的是「切布局」。
4. **不要在小地图上做节点级操作** —— 小地图的作用是「导航」，塞进编辑操作只会误触。
5. **不要把设置项继续往设置面板里堆** —— 现在设置面板已经有 20+ 项。
   新东西优先做成**画布内的就地操作**（悬停操作条、右键菜单），
   用户不用离开画布就能改。

## 建议的落地顺序

```
第一步（一次迭代内可完成，收益最大）
  P0-2 结构操作反馈   ← 纯前端，独立，见效最快
  P0-3 视图状态跟文档走 ← 复用已有属性管线

第二步（需要动 actions.ts）
  P0-1 批量操作条     ← 依赖结构操作支持批量

第三步（纯打磨）
  P1-1 / P1-2 / P1-3 / P1-4
```

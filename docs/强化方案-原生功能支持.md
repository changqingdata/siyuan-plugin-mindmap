# 大纲导图 · 思源原生功能支持强化方案

> 基于 2026-09-20 的真机实测（`tests/kernel/inline-coverage.mjs` / `image-probe.mjs`）与源码走查。
> 本文档只做分析与方案设计，**未修改任何插件源码**。

## 零、结论先行

**你的判断是对的：原理上早就支持了。** 解析层保留了 `innerHTML`（`parser.ts:65`），渲染层原样写入（`renderer.ts:953` 的 `txt.innerHTML = n.html`），CSS 也覆盖了主要行内元素（`index.css:433-490`）。所以双链、公式、加粗这些**本来就是通的**。

实测下来，真正有问题的只有 5 处，而且全是**边界**问题，不是能力问题：

| # | 问题 | 性质 | 优先级 |
|---|---|---|---|
| 1 | 在导图里改名 = 抹掉该节点全部格式 | **数据破坏** | P0 |
| 2 | 降级/升级走副本路径时，整棵子树丢格式 | **数据破坏** | P0 |
| 3 | 纯图片 / 纯公式的列表项被当空节点丢弃 | 功能缺失 | P1 |
| 4 | Protyle 的 UI 外壳（操作按钮等）被当成内容带进节点 | 脏数据 | P1 |
| 5 | 导出的 SVG/PNG 缺宿主 CSS，公式与颜色会失真 | 导出失真 | P2 |

## 一、实测盘点：现在到底支持到什么程度

做法：造一个列表，每项演示一种行内功能；对比「源列表 DOM」与「导图 `.mm-txt` 的 DOM」，
再用 `getComputedStyle` 实测样式（**样式表里写了规则 ≠ 真的生效**）。

### ✅ 已经完整支持（HTML 保留 + 样式生效）

| 功能 | 思源 DOM | 导图实测计算样式 |
|---|---|---|
| 加粗 | `<span data-type="strong">` | `font-weight: 650` ✓ |
| 斜体 | `<span data-type="em">` | `font-style: italic` ✓ |
| 下划线 | `<span data-type="u">` | `text-decoration: underline` ✓ |
| 删除线 | `<span data-type="s">` | `line-through` ✓ |
| 行内代码 | `<span data-type="code">` | 等宽字体 + 底色 ✓ |
| 高亮 | `<span data-type="mark">` | 黄底 ✓ |
| 上标 / 下标 | `<span data-type="sup|sub">` | `font-size: 10.5px` ✓ |
| 行内公式 | `<span data-type="inline-math">` + KaTeX | KaTeX 正常渲染 ✓ |
| 块引用（双链） | `<span data-type="block-ref" data-id>` | 下划线 + 紫色 ✓ |
| 链接 | `<span data-type="a" data-href>` | 有 CSS 规则 ✓ |
| 标签 | `<span data-type="tag">` | 圆角底 + 11.9px ✓ |
| 文字颜色 | `<span data-type="text" style="color: var(--b3-font-color1)">` | 内联样式保留 ✓ |
| 背景色 | `<span data-type="text" style="background-color: …">` | 内联样式保留 ✓ |
| 字号 | `<span data-type="text" style="font-size: 22px">` | 内联样式保留 ✓ |

> ⚠️ 颜色/字号能生效，**靠的是思源全局 CSS 里的 `--b3-font-color1..13` 变量**（插件 DOM 也在思源页面里，宿主 CSS 顺带生效）。
> 换个主题、或者导出到思源之外，这层就没了。见 P2-4。

### ❌ 实测不成立

| 功能 | 实测结果 | 归属 |
|---|---|---|
| 纯图片列表项 | **整个节点消失**（源列表 3 项 → 导图 2 个节点） | 插件 |
| 图片（图文混排） | 能显示（`naturalWidth: 120` ✓），但**会把节点宽度撑破**（310px > `max-width: 240px`） | 插件 |
| 图片项携带的 UI 外壳 | `<span class="protyle-action protyle-icons">` + `#iconMore` 的 SVG 被一起带进节点 | 插件 |
| 高亮 `==高亮==`（markdown 语法） | 思源的 markdown 导入器**不认**，原样留成纯文本 | 思源导入器，非插件问题 |
| `[[双链]]`（markdown 语法） | 同上，导入器不解析；**编辑器里用 `[[` 补全插入的是真双链，插件能正常显示** | 思源导入器，非插件问题 |
| `<span style="color:…">`（markdown 里写 HTML） | 导入器会转义成纯文本 | 思源导入器，非插件问题 |

> 最后三条是**探针的坑**，不是插件的坑：思源的 markdown 导入器能力有限，用它造测试数据会得出错误结论。
> 必须用 `dataType: "dom"` 注入思源真实的行内 HTML，才等于用户在编辑器里用工具栏做出来的东西。

## 二、五个问题的根因

### P0-1 ⚠️ 在导图里改名 = 抹掉该节点全部格式（数据破坏）

**实测证据**：

```
改之前： - {: id="…5z30ojz" …}加粗 **粗体** 斜体 *斜体*
进编辑态：编辑框里的 HTML 是「加粗 粗体 斜体 斜体」   ← 格式已经没了
改之后： - {: id="…5z30ojz" …}改过                      ← 整条被替换
加粗是否还在：✘ 没了
```

**代码路径**（`renderer.ts:1437-1483`）：

```ts
const original = n.text;          // 纯文本
const savedHtml = n.html;         // 格式在这里备份了
txt.textContent = original;       // ← 进编辑态的瞬间就把 HTML 换成纯文本
…
const next = (txt.textContent ?? "").replace(/\s+/g, " ").trim();
txt.innerHTML = savedHtml;        // 视觉上还原了
if (commit && next && next !== original) this.cb.onRename(n, next);  // ← 但写回的是纯文本
```

三个叠加的问题：

1. **进编辑态就看不见格式了** —— 用户以为自己只是在改字；
2. **写回的是 `textContent`** —— `renameNode` 把纯文本写进内核，双链、加粗、公式一起没了；
3. **没有任何提示** —— 静默、不可逆（插件的撤销栈能整体回滚，但用户得先意识到「我改坏东西了」）。

这条是**最高优先级**：它会把用户精心维护的内容毁掉，而且看起来像「正常改名」。

### P0-2 ⚠️ 降级 / 升级走副本路径时，整棵子树丢格式

`actions.ts:37-42` 的副本路径（`insertBlock(serializeSubtree(node))` + `deleteBlock`）用于
「内核 `moveBlock` 表达不了的边界位置」（`moveBlock` 只有 `previousID`，没有 `nextID`）。

而 `tree.ts:53-58` 的 `serializeSubtree` 用的是 **`escapeMd(node.text)`** —— 纯文本：

```ts
const line = `${indent}${markerOf(node)} ${escapeMd(node.text)}`;
```

也就是说：**在边界位置做一次降级/升级，整棵子树的格式会被静默重建成纯文本**（而且块 ID 会重建）。
「复制节点」（`renderer.ts:1408/1419/1532`）走同一条路。

### P1-3 非文字内容被当「空节点」丢掉

`parser.ts:68-69`：

```ts
// 既没文字也没子节点的空列表项直接丢弃
if (!text && children.length === 0) continue;
```

`text` 来自 `contentEl.textContent`。而：

- 纯图片项的 `textContent` 是空白 → **整个节点消失**（实测：3 项 → 2 节点）
- 纯公式项、纯 emoji 项、只含标签的项同理（`<img>` 没有文本、KaTeX 的文本是公式源码）

这个判据本意是「过滤编辑器里残留的空行」，但把「有内容、只是没有文字」的项误伤了。

### P1-4 Protyle 的 UI 外壳被当成内容

`sanitizeInline`（`parser.ts:130-138`）只删了 4 个属性，没有结构层面的清洗。实测被带进节点的垃圾：

```html
<div class="protyle-attr"></div>                          <!-- 块属性标记，编辑器的 UI -->
<span class="protyle-action protyle-icons">…</span>       <!-- 悬停时出现的那排操作按钮 -->
  <span class="protyle-icon protyle-icon--only">
    <svg class="svg"><use xlink:href="#iconMore"></use></svg>   <!-- 「更多」图标 -->
<span> </span>                                            <!-- 图片周围的占位 -->
```

连带两个副作用：

- `contenteditable="false"` 被删掉了，但它是 KaTeX 的 `render-node` 和图片 `span` 的保护属性 —— 删掉之后在编辑态可能被改坏；
- `img` 的 `loading="lazy"` 被保留，而源列表是 `display: none`（`index.css:23-25`），
  **源列表里那些图永远不会触发懒加载**（实测 `naturalWidth: 0`）。

> 好消息：导图里那份 `img` 是插件自己写进可见区域的，**能正常加载**（实测 `naturalWidth: 120`）。
> 所以图片不是「加载不出来」，而是「纯图片节点被丢了」+「UI 外壳被带进来了」。

### P2-5 导出 / 复制走纯文本，格式在旁路丢失

| 路径 | 现状 | 后果 |
|---|---|---|
| 导出 SVG/PNG（`exporter.ts:49-67`） | 只内联插件自己的 CSS | KaTeX 样式、`--b3-font-color*` 变量都不在里面 → **公式是乱的、颜色是黑的** |
| 导出 PNG 光栅化 | `foreignObject` → canvas | 图片可能拿不到（跨域/时序），KaTeX 字体也不保证 |
| 复制节点（`serializeSubtree`） | `escapeMd(node.text)` | 格式丢 |
| 搜索（`renderer.ts:1738`） | `n.text.toLowerCase().includes()` | ✅ 没问题，`textContent` 含格式文字 |

## 三、强化方案

### P0 · 先堵住数据破坏

#### 方案 A（推荐）：双击改为「交给 Protyle 就地编辑」

不再自己实现编辑框，而是**把光标送回思源的源列表段落**：

```
双击节点
  → 源列表取消隐藏（或临时展开该分支）
  → scrollIntoView({block:'center'})
  → 对该段落设置 selection 并 focus
  → 导图保持挂载（`.mm-root` 还在），用户改完自动同步回来（已有的签名重渲染机制）
```

- **优点**：零格式损失；思源的输入法、双链补全、公式编辑、粘贴、快捷键全部可用；实现量很小
- **代价**：视线要在「导图」和「列表」之间跳一次
- **折中**：把「编辑」按钮的语义明确成「跳到原文改」，图标 + tooltip 说清楚

#### 方案 B（后续增强）：富文本就地编辑

保留 `contenteditable` 里的 HTML，提交时把 HTML 转成思源的行内 markdown 写回。

需要写一个**行内 HTML → markdown 序列化器**，建议只覆盖可无损往返的子集：

| 元素 | markdown | 往返可靠性 |
|---|---|---|
| `[data-type="strong"]` | `**x**` | 无损 |
| `[data-type="em"]` | `*x*` | 无损 |
| `[data-type="u"]` | `<u>x</u>` | 无损 |
| `[data-type="s"]` | `~~x~~` | 无损 |
| `[data-type="code"]` | `` `x` `` | 无损 |
| `[data-type="mark"]` | `==x==` | 无损 |
| `[data-type="sup|sub"]` | `^x^` / `~x~` | 无损 |
| `[data-type="text"]`（颜色/字号） | `<span style="…">x</span>` | 需实测 |
| `[data-type="block-ref"]` | `<span data-id="…">x</span>` | **有损**：块引用必须原样保留 `data-id`，不能走 markdown |
| `[data-type="inline-math"]` | `$…$` | **有损**：建议直接保留原 span |

**关键取舍**：双链和公式**不要走 markdown 往返**，直接从 `savedHtml` 里把对应 span 原样搬回来。
更稳的做法是「**只替换被改动的那段文本节点，其余节点原样保留**」—— 用 DOM diff 而不是序列化。

#### 方案 C（最小改动，兜底）

保持现在的纯文本编辑，但：
- 节点**含非纯文本内容时**，编辑态在编辑框上方显示一行警告「此节点含双链/公式/格式，改字会丢失」；
- 或者干脆**禁用**这类节点的就地编辑，双击直接跳到原文（其实就是方案 A）。

**建议**：**A 立刻做（改动小、收益大），B 作为下一轮**。

#### P0-2 的修法

`serializeSubtree` 增加「保格式」分支：用 `node.html` 而不是 `node.text` 生成 markdown
（把 HTML 直接写进 markdown 里，思源的 markdown 导入器能识别 `**`、`<u>`、`$…$` 等；
双链和公式则用 `<span data-type="block-ref" data-id="…">` 原样内嵌）。

更稳的做法是**绕开 markdown**：副本路径改用「`/api/block/getBlockKramdown` 取原文 →
`insertBlock` 插入原文」，与撤销功能里已经验证过的 kramdown 快照同源。
注意这条路径本身有已知坑（见 SKILL.md「用 kramdown 快照还原必须写两次」）。

### P1 · 补齐边界

1. **空节点判据**（`parser.ts:69`）改成「既没文字、也没子节点、也没非文字内容」：

   ```ts
   const hasRich = !!contentEl?.querySelector(
       'img, [data-type="img"], [data-type="inline-math"], [data-type="tag"], [data-type="block-ref"], [data-type="a"]'
   );
   if (!text && !hasRich && children.length === 0) continue;
   ```

2. **结构白名单清洗**（`sanitizeInline` 升级为 DOM 级清洗）：

   ```ts
   const DROP = [".protyle-attr", ".protyle-action", ".protyle-icons", ".protyle-icon", ".protyle-icon--only"];
   for (const sel of DROP) root.querySelectorAll(sel).forEach(el => el.remove());
   // 图片：把懒加载的 data-src 搬到 src，并去掉 loading="lazy"
   root.querySelectorAll("img").forEach(img => {
       const real = img.getAttribute("data-src") || img.getAttribute("src") || "";
       if (real) img.setAttribute("src", real);
       img.removeAttribute("loading");
       img.removeAttribute("data-src");
   });
   // 空的占位 span（图片周围的「 」）也一并清掉
   ```

   > 现在 `sanitizeInline` 是字符串正则（`parser.ts:130-138`）。要按元素删，得先 `DOMParser`/`template` 解析成 DOM 再序列化 ——
   > 或者更省事：在解析时就对 `contentEl.cloneNode(true)` 做 DOM 清洗，再取 `innerHTML`。
   > **克隆再清洗**是关键：绝不能直接改源 DOM，那是思源自己的编辑器内容。

3. **图片尺寸约束**（`index.css` 补规则）：

   ```css
   .mm-root .mm-txt img { max-width: 180px; max-height: 72px; border-radius: 4px; object-fit: cover; vertical-align: middle; }
   .mm-root .mm-txt [data-type="img"] { display: inline-flex; align-items: center; }
   ```

   现在实测节点宽度会被图片撑到 310px（超过 `.mm-txt` 的 `max-width: 240px`，`index.css:421-427`）。

4. **不要依赖宿主 CSS**：`--b3-font-color1..13` / `--b3-font-background1..13` 是思源全局变量。
   建议在 `.mm-root` 上做一层映射兜底，例如
   `--b3-font-color1: var(--mm-font-color1, #d23f31)`，这样导出到思源之外也有颜色。

### P2 · 交互增强（让「原生功能」真的可用）

1. **双链 / 链接可点击**（当前完全点不动）

   现在 `mousedown` 被 `preventDefault`（为了保焦点，见 `renderer.ts:1033-1037`），单击又是「选中节点」，
   所以链接和双链**没有任何办法打开**。建议二选一：

   - **`Ctrl` / `Alt` + 单击**打开：`[data-href]` → `window.open`；`[data-type="block-ref"]` → 用 `data-id` 打开页签
   - **悬停 300ms 在节点右上角浮出一个小按钮**（打开链接 / 打开双链）

   推荐前者（零 UI 噪音，且和思源「Ctrl+单击打开链接」的习惯一致）。

2. **双链悬停预览**：复用 `/api/block/getDocInfo` + 自绘 popover，展示被引用块的上下文。

3. **图片点击放大**：节点内图片是缩略图，点击后弹层看原图。

4. **长 URL / 长标签的换行**：`[data-type="a"]`、`[data-type="tag"]` 加 `word-break: break-all`，
   否则一个长 URL 会把节点撑得很宽。

### P3 · 导出保真

1. **内联 KaTeX 的最小 CSS**（否则导出的公式是散架的文字）；
2. **把思源颜色变量解析成具体值** —— `exporter.ts` 已经有 `resolveCssValue` 处理 `--mm-*`，
   把 `--b3-font-color*` 也纳入即可；
3. **导出前把图片转成 data URI**（`fetch` → base64），否则 `foreignObject` + canvas 光栅化经常拿不到图；
4. 提供「**导出为 HTML**」作为兜底 —— 不受 `foreignObject` 支持面的限制（很多看图工具不认 `foreignObject`）。

## 四、优先级与建议顺序

| 优先级 | 项 | 改动量 | 风险 |
|---|---|---|---|
| **P0** | 改名保格式（方案 A：双击跳原文） | 小 | 低 |
| **P0** | 副本路径保格式（`serializeSubtree` 用 kramdown） | 中 | 中（kramdown 往返有已知坑） |
| **P1** | 空节点判据 + 结构白名单清洗 + 图片尺寸 | 中 | 低 |

| **P2** | Ctrl+单击打开双链/链接 | 小 | 低 |
| **P2** | 图片点击放大、长 URL 换行 | 小 | 低 |
| **P3** | 导出内联 KaTeX + 图片转 data URI | 中 | 中 |
| **P3** | 富文本就地编辑（方案 B） | 大 | 高（往返失真） |

**建议顺序**：P0 两条 → P1 三条 → P2 两条 → 再评估 P3。

## 五、验收方式（已经就位）

这轮为了做分析，新增了两个可复跑的诊断脚本（**只加测试，没动插件源码**）：

```bash
npm run kernel:inline        # 行内格式覆盖度盘点：逐项对比 源列表 DOM vs 导图 DOM + 实测计算样式
npm run kernel:image         # 图片专项：纯图片节点、图文混排、懒加载、URL 解析
npm run kernel:inline:edit   # 进编辑态改名，验证格式是否被抹（数据破坏专项）
```

建议把它们固化成回归门槛，补上这几条断言：

- 每个演示项在导图里的 `data-type` 计数 ≥ 1（格式没被丢）
- **纯图片项必须产出节点**（现在是 3 项 → 2 节点）
- 导图节点的 `innerHTML` 里**不含** `protyle-attr` / `protyle-action` / `protyle-icons`
- 改名后 `getBlockKramdown` 里原来的 `data-type="strong"` / `block-ref` 仍在
- 导出 SVG 里含 KaTeX 样式、颜色是具体值而不是 `var(--b3-…)`

## 附：一句话回答「原理上支持吗」

**支持。** 解析层留了 `innerHTML`，渲染层 `txt.innerHTML = n.html` 原样写入，CSS 也覆盖了主要行内元素 ——
双链、公式、加粗、颜色这些**本来就是通的**（实测计算样式全部生效）。

缺口全在三个「边界」上：

1. **空节点判定**把「有内容但没文字」的项误伤（纯图片/纯公式消失）；
2. **清洗不够**，把 Protyle 的 UI 外壳当内容带进来，又把该留的保护属性删掉；
3. **两条旁路走纯文本** —— 改名（`textContent`）和副本路径（`escapeMd(node.text)`），
   会**静默地把格式抹掉**。这两条是数据安全问题，应该最先修。

## 实施中才暴露的三个坑

1. **`[class*="protyle-"]` 必须用前缀匹配。**
   第一版按方案写的 `.protyle-action`，结果 `.protyle-action__drag`（图片左上角那个拖拽手柄）
   **匹配不到** —— BEM 修饰符是另一个类名。它一路被带进了节点，探针截图里才看出来。
   同理还有 `.img__net`（图片加载失败时的网络图标占位），它不在 `protyle-` 前缀下，得单独列。

2. **跳回源编辑时不能全选。**
   第一版照搬了原来的「全选方便直接改写」，探针立刻打脸：一打字就替换掉整段内容，
   连带把加粗、双链、公式一起清掉 —— 正好是我们想避免的那件事。
   改成 `range.collapse(false)` 把光标落在**末尾**：改错别字最安全，要全选用户自己 Ctrl+A。

3. **`--b3-*` 颜色只能在导出时固化，不能在 `.mm-root` 上重定义。**
   在插件根元素上重新声明 `--b3-font-color1…13` 会**覆盖**宿主的真实配色（用户换主题就跟着坏），
   反而更糟。正确位置是导出那一刻 —— 那时页面里变量有值，用 `getComputedStyle` 读出来写死即可。

## 新增的可复跑回归

```bash
npm run kernel:inline         # 覆盖度盘点 + 清洗干净度 + 截图
npm run kernel:inline:edit    # 双击含格式节点 → 跳回源编辑；改字后格式仍在
npm run kernel:inline:copy    # 快速复制含格式节点 → 格式随行
npm run kernel:inline:links   # 裸单击不打开、Ctrl+单击打开链接
npm run kernel:inline:all     # 上面四个串起来跑
npm run kernel:copy           # markdown 通道的能力矩阵（哪些语法能过）
npm run kernel:image          # 图片专项（纯图片节点 / 图文混排 / 懒加载 / URL）
```

**建议固化成门槛的 5 条断言：**

1. 导图节点数 **==** 源列表项数（纯图片、纯公式项不能丢）
2. 导图 `.mm-root` 里 `[class*="protyle-"]` 的计数 **== 0**
3. 双击含格式节点后 `[data-mm-editing]` **不存在**，且 `document.activeElement` 落在 `.protyle-wysiwyg` 内
4. 改字前后 kramdown 里 `**` / `((` / `$` / `<u>` 的**计数不减少**
5. Ctrl+单击链接后 `window.open` 被调用，裸单击**不被调用**
